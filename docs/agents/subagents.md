# Built-in subagents

## Bounded invocation contract (Pi Web only / installed Pi SDK 1.0.3)

A profile is a **resource bundle**, not a permanent role or execution strategy. The lead chooses all six execution decisions on **every** `Agent` call, including resume. There are no profile, parent, or prior-invocation execution fallbacks. This is a Web extension contract, not a CLI/core SDK change.

Exact `Agent` schema (required task/label plus all execution choices):

```text
prompt: string                                      required
description: string                                 required
model: string matching ^[^/\\s]+/[^\\s]+$             required (provider/modelId)
thinking: off|minimal|low|medium|high|xhigh|max         required
max_turns: integer, 1..9007199254740991                required
inherit_context: boolean                            required
run_in_background: boolean                          required
isolation: off|worktree                              required
subagent_type: string                                optional resource bundle
resume: string                                       optional existing child ID
input_files: string[]                                optional, max 8 files
```

- Both schema and runtime validate decisions. `prepareArguments` validates raw model arguments before SDK TypeBox coercion: strings/numbers are not booleans and numeric strings are not turn limits. Missing/invalid choices fail before launching. Explicit model IDs resolve through the installed model runtime; unsupported thinking levels fail rather than silently clamping.
- New starts honor explicit `false` and `off`. `off` shares the parent's cwd; `worktree` uses the existing isolation lifecycle. Only explicit `inherit_context: true` imports the bounded active parent context on start. For replace-mode and tool-free exact prompts, that context travels in the delegated task so the exact profile system prompt does not discard it. Profile frontmatter/API/editor `model`, `thinking`, `max_turns`, `inherit_context`, `run_in_background`, and `isolation` remain legacy/shared-runtime fields and **are ignored by Web execution**, even if visible in the existing Agents editor. Resource selectors/tools/prompt still apply. Profile models are not advertised as execution defaults.
- Resume applies the selected model with real SDK `setModel`, then effort with `setThinkingLevel` (the model setter can otherwise select defaults). `max_turns` is a fresh budget per invocation; foreground/background is explicit. Resume retains child history and the fixed `resourceSnapshot`, never reloads a profile to widen resources or re-imports parent history.
- Resume requires `inherit_context: false` and the existing isolation mode (identified by persisted `worktreePath`, otherwise `off`). Attempts to add/remove isolation or resume a removed worktree fail **before reopening/setters/journal writes**, with guidance to start a new child for different inheritance/isolation. A retained worktree may resume in place; resume does not create a new worktree. Normal isolation cleanup still belongs to the start lifecycle.
- There is no token budget, new scheduler, or new-context fork. Limits count SDK `turn_end`: wrap-up is requested at N completed turns and abort at N+1. They cannot bound tool/external-job duration or stop external work independently.

**Runtime qualification:** tests create fresh SDK-host sessions against installed 1.0.3. Source HMR does not guarantee that already-live Web parent wrappers replace their captured inline extension factories/controllers; `/reload` is not guaranteed sufficient for those wrappers. This change does not mutate active wrappers or restart the server. New SDK-host sessions qualify the contract; existing live sessions may retain the old contract until their wrapper is naturally replaced.

Evidence: `lib/subagent-policy.integration.test.mjs` uses native SDK faux-provider lead-to-tool-to-child requests (start and resume), conflicting legacy defaults, raw malformed/missing choices, real resume setters and N/N+1 budget, and pre-mutation unsupported/inheritance/isolation/removed-worktree rejection. No API/GPU calls. `lib/subagent-telemetry.integration.test.mjs` retains disk persistence, exact turn counts, resume resets and unsubscribe/signal cleanup. Selected resources/reopening remain covered by `lib/subagent-resources.integration.test.mjs`.

## Selective resources (Pi Web / Pi SDK 1.0.3)

Custom profiles can use:

```yaml
skills: [shared-memory]
extensions: [./.pi/extensions/coordexp-rtk.ts]
mcp_servers: [codegraph, shared-memory]
mcp_tools: [codegraph/codegraph_explore, shared-memory/search, shared-memory/read]
load_skills: true
load_extensions: true
```

- `skills` accepts exact discovered names, or legacy boolean / `all` / `none`. A list actually filters SDK `getSkills()` and skill commands/routing metadata; full skill bodies are **not** eagerly injected. `load_skills: false` disables even a list. Missing settings default off.
- `extensions` accepts explicit JS/TS file paths (relative to child cwd), or legacy boolean / `all` / `none`. Lists use SDK `noExtensions` plus `additionalExtensionPaths`, not whole-extension discovery. `load_extensions: false` disables even listed files. Legacy package-name lists are preserved by older clients but unsupported as loaders and select no files; migrate to explicit paths. `ext:` tool selectors retain their existing tool-selection meaning, not extension-file loading.
- `mcp_servers` is an array of exact raw mcp.json server names; absent/empty loads no configured servers. MCP does not require `load_extensions`. `mcp_tools` is an array of exact raw `server/tool` selectors, **not** sanitized `mcp__…` names. Absent means all eligible tools of selected servers; `[]` means none. No wildcards. Disabled/hidden configuration remains unavailable. Selected tools are SDK deferred tools, discovered through `tool_search`, not an eagerly declared catalog. MCP resource-list/read helpers and the child `/mcp` manager are not enabled by this interface.
- Each list is capped at 64 selectors; names/selectors at 256 characters (skill names 64), extension paths at 1024. Profile API camelCase fields are `skillNames`, `extensionPaths`, `mcpServers`, `mcpTools`. Existing booleans remain master switches. The Agents editor exposes all four lists with explicit All / Selected modes where applicable. API omissions preserve stored lists; send `[]` to select none, or `null` to remove a stored list (legacy boolean behavior for skills/extensions, all selected-server tools for MCP tools, no servers for MCP servers).
- When global and project profile directories resolve to the same physical directory (for example `PI_CODING_AGENT_DIR=<cwd>/.pi`), discovery lists that source once under global ownership. Distinct directories retain global → workspace → project override precedence.
- MCP-enabled children receive a frozen native `caller_context` (child session ID, actual cwd, harness/actor) in their profile prompt, including replace mode. In-process children share the parent's environment; `PI_SESSION_ID` is **not** child identity. No project/task ID is inferred or borrowed. The same native identity survives reopening; Shared Memory still validates cwd registration and scope.
- Selection is persisted in `resourceSnapshot` and reused at reopen/resume even after profile edits. Names/paths, not resource bytes or schemas, are frozen; file contents and mcp.json connection details can still change. Old snapshots retain boolean behavior and no configured MCP. Project trust and `PI_WEB_DISABLE_MCP` still apply; MCP uses the existing scrubbed Pi Web transport and SDK MCP extension, not a new client. Unlike normal Web MCP sessions, this thin child adapter does not publish host status, idle-release connections, or resync config before every prompt; config is read on extension binding/reload/reopen.
- This minimizes context, not permissions. Trusted loaded extensions can still add behavior/tools/servers, and skills/files remain readable through ordinary tools. `noContextFiles` is retained: place a **pointer** to the user-wide contract in each custom profile prompt; a pointer is not automatic injection. Do not blindly copy the parent or whole contract into each child. The lead owns the pointer and profile files.
- Omitted `subagent_type` prefers enabled `general-purpose`, otherwise the first enabled custom profile (then any enabled profile), rechecking current profiles at dispatch. Ordering follows the profile provider (the standard provider sorts by display name), not a hardcoded preference for a custom profile ID.

Evidence: `lib/subagent-resources.integration.test.mjs` exercises real SDK child loading and faux-provider consumer requests, selected stdio MCP execution, excluded-server non-start, and selection retention across reopening. No provider API calls are used. `app/api/subagents/profiles/route.test.mjs` checks API round-trips/toggles/resets/validation; `components/agent-resource-editor.test.mjs` checks editor serialization.

## Bounded observation

- New start/resume invocations persist optional `telemetry` in the existing `pi-web:subagent-result` entry: `{ turnCount, turnCountBasis: "turn_end", terminationReason }`. The count is exact observed SDK `turn_end` events, not assistant records, tool calls, or user turns. It resets on resume; every new invocation now requires an explicit `maxTurns`. Queued aborts count zero and release their subscription/signal listener. An already-aborted foreground caller also skips the model prompt on both start and resume; background invocations remain detached from the parent signal. Reasons distinguish `completed`, `abort-requested`, `max-turns`, `provider-error`, and `runtime-error`. Old journals have no such evidence and remain unknown.
- Setup-only queued aborts need a durable result despite SDK deferred first-write behavior. `appendSubagentResult` writes that same journal exclusively when it does not yet exist, then reloads the same manager; it creates no second event log. This Pi 1.0.3 seam is covered by `lib/subagent-telemetry.integration.test.mjs`, including disk reopen, start/resume isolation and listener cleanup.
- `subagentToolDetails().observation` is a terminal-only read-time projection, using the existing session-reader fingerprint cache and refusing files over 16 MiB. `lib/subagent-observation.ts` selects the lifecycle interval ending at the matching completion (scope explicitly `lifecycle-inferred`) and reuses `computeSessionStats`, including auxiliary/tool/compaction/cache-warming usage. These are recorded totals, not a billing guarantee for failures with missing usage. No transcript/log bodies are copied into details or the parent's model text.
- Response metadata distinguishes selected `model` from optional provider-reported `responseModel`, and Pi `thinkingLevel` from optional `providerThinkingLevel`. Missing routing/effort remains null; mixed variants are retained, capped at eight with an explicit truncation flag. Session/worktree/structured full-output pointers are capped at sixteen; accounting is not truncated with the pointers. A pointer is not a durability or integrity certification. There is no new dashboard or artifact manifest.
- Existing N/N+1 limit semantics now apply equally to start and resume: each invocation's `maxTurns` requests wrap-up at N completed turns and aborts after N+1; the budget result can still have legacy status `completed`, qualified by `terminationReason: "max-turns"`. Do not advertise these controls as a strict external job or token budget.

## Built-in subagents
- The global `builtInEnabled` in `~/.pi/agent/agents/settings.json` is off when the file or field is absent and when the file is malformed (fail closed); writes are atomic and keep unknown fields. The inline extension factory is always present, so a reload can apply the switch, but registers no tools while off; after changing it the user must reload the session explicitly, and `Agent` dispatch re-checks the setting so a stale call cannot start a subagent. When on, only a recognized legacy `pi-subagents` extension registering a reserved tool (`Agent`, `get_subagent_result`, `steer_subagent`) is removed, along with the conflict errors it caused; unrelated extensions stay. ADR 0003.
- The three tools register with `exposure: "model-only"`, so `ctx.executeTool()` (a codemode script) cannot start, collect or steer a subagent: a script-started run would record the nested call id (`<codemode call>/<n>`) as its `parentToolCallId`, which no transcript entry carries, and the chat would lose its link to the child session. `lib/subagent-extension.integration.test.mjs` pins this against a real `AgentSession`.
- `queued` is a pending status, not a failure: result text reports it as queued, and `get_subagent_result({ wait: true })` waits through it before collecting a terminal result or suppressing its notification.
- A run stays in `getSubagentRuns()` from dispatch until its result entry is written, so `get()` reports a persisted `running` / `queued` status with no result and no running wrapper as `interrupted`: its process stopped and nothing will finish it (otherwise `get_subagent_result({ wait: true })` polls forever after a restart).
- Built-in profiles (`general-purpose`, `explore`, `plan`) are switched off by name in that file's `disabledBuiltIns`, never by copying them to a `.md` file (ADR 0005). `builtInProfiles()` stamps `enabled` onto them so the panel, the `Agent` tool description and `resolveSubagentProfile` agree. Writes are minimal edits that keep names they did not touch, including ones no built-in claims; reading fails *open* (the feature switch has already failed closed). `PATCH /api/subagents/profiles` with `scope: "builtin"` writes it; `PUT`/`DELETE` refuse that scope. A same-name file replaces the built-in outright and is switched off through its own frontmatter. Only the switch is live for a built-in; the rest of the form is read-only.
- `notifyParent` skips a background run's completion notification when the parent already collected that result with `get_subagent_result`, which marks it consumed. The mark names the run (`sessionId` + `completedAt`), never just the session, since `resume` reuses the session id; `resume` keeps the mark. While the parent `isRunning()` (often still inside that poll) the notification is held and the mark re-checked; an idle parent is notified at once.
- The notification is a `custom` message, which pi's `convertToLlm` replays as a plain `user` turn, so `subagentNotificationText()` prefixes `SUBAGENT_NOTIFICATION_PREFIX`; otherwise compaction files the report under the user's Goal / Constraints. Keep the prefix in code, never in a profile prompt, so the model cannot drop it. A `resume`d run's notification adds a line saying it supersedes the earlier report, which it would otherwise repeat word for word. Foreground `Agent` and `get_subagent_result` results are `toolResult`s and keep the bare `subagentFinalText()`.
- Profile toggles and the editor's edit/duplicate path retain shared-runtime `color`, `isolation`, and `persist_session`, even though Web execution ignores profile isolation in favor of each invocation's explicit choice.
- Profile files (`~/.pi/agent/agents/*.md`, project `.pi/agents/*.md`) are shared with other runtimes: a save round-trips every frontmatter key outside `MANAGED_FRONTMATTER_KEYS` (`lib/subagents.ts`; e.g. `name`, `allowed_subagents`, `exclude_extensions`, `disallowed_tools`) and carries foreign `ext:` tool selectors through. The pi-subagents aliases `skills` / `extensions` are seeded on first save and kept in step with `load_skills` / `load_extensions` while they hold a boolean (or `none` / `all`); a foreign named whitelist such as `extensions: pi-advisor-flow` is preserved unless the API/editor explicitly supplies a replacement list, and the flags fall back to the aliases when `load_skills` / `load_extensions` are absent.
